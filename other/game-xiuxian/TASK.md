# 百世修仙：四文件收敛实施计划

## 1. 目标与边界

将项目收敛为一个适合直接打开和维护的原生前端小游戏，运行时代码只保留以下四个文件：

```text
game-xiuxian/
├── index.html       # 页面骨架、游戏画布、DOM UI
├── index.js         # 全部运行时逻辑、Phaser 场景、UI 交互、存档
├── data.json        # 静态游戏配置和可序列化数据
├── style.css        # 全部样式
├── data/            # 图片、音频、字体等资源
└── lib/phaser.min.js # 第三方 Phaser 运行库，保留
```

本次不新增 `src/` 下的业务模块，不拆分新的 JS/CSS 文件，不引入 React、构建工具或状态管理框架。`README.md`、`TASK.md` 和第三方 `lib/phaser.min.js` 属于项目说明/依赖文件，不计入四个运行时源码文件。

## 2. 当前情况盘点

- 根目录的 `index.html` 已有完整 DOM 结构和大部分样式，但入口仍指向 `src/main.js`。
- 根目录 `index.js`、`data.json`、`style.css` 当前为空，需要作为最终实现文件使用。
- 运行时代码分散在 `src/app`、`src/core`、`src/data`、`src/effects`、`src/input`、`src/systems`、`src/ui`。
- 主要业务集中在 `src/core/main-scene.js`、`src/systems/combat-system.js`、`src/effects/skill-effects.js`、`src/ui/index.js`、`src/core/state.js` 和 `src/core/save.js`。
- 当前敌人、技能、区域、境界、装备、成就、商店等静态定义位于 `src/data/index.js`。
- 当前纹理主要由代码生成，暂未发现已建立的根目录 `data/` 资源目录；需要先盘点未来确实需要外置的图片、音效和字体。
- 现有存档 key 为 `xiuxian_save`，格式标记为 v1；迁移期间必须继续兼容已有存档。

## 3. 最终职责设计

### `index.html`

- 保留 `<!doctype html>`、移动端 meta、标题和游戏画布。
- 保留 HUD、热栏、顶部/底部导航、角色/背包/技能/成就/商店、突破、死亡、加载和提示等 DOM 容器。
- 删除所有 `<style>` 内嵌样式，统一改为 `<link rel="stylesheet" href="style.css">`。
- 删除所有 `onclick` 和其他内联业务事件，改为 `data-action` 或由 `index.js` 统一绑定。
- 只加载 `lib/phaser.min.js` 和根目录 `index.js`。
- 保证 DOM id、data 属性和现有 UI 行为在迁移前后保持一致，减少游戏逻辑改写范围。

### `style.css`

- 完整承接 `index.html` 现有 `<style>` 内容。
- 按页面基础、HUD、热栏、面板、按钮、导航、提示、摇杆、移动端适配的顺序整理。
- 保留现有视觉主题、响应式断点、安全区域和 Phaser 画布层级。
- 将动态宽度、显示状态、冷却状态等从内联 style 改为 class 或 CSS 自定义属性，由 `index.js` 更新。
- 资源 URL 统一使用 `data/` 下的相对路径；没有实际资源需求的程序化纹理不额外生成空文件。

### `data.json`

将 `src/data/index.js` 中的静态定义转为合法 JSON，至少包含：

- `realms`：境界、层数、属性加成、突破条件。
- `skills`：技能 id、名称、类型、伤害、范围、冷却、颜色、描述。
- `zones`：区域、距离范围、怪物等级和视觉参数。
- `bestiary`：敌人模板、属性、攻击类型、掉落参数。
- `bossNames`：Boss 名称池。
- `achievements`：成就条件描述、奖励和展示信息；移除不可序列化的 `check` 函数。
- `shopItems`：商店商品、价格和效果描述。
- `equipment`：部位、基础属性、品质倍率、名称池和颜色。
- `world`、`combatTuning` 等平衡参数。
- `assets`：资源 id 到 `data/` 相对路径的映射，仅记录实际需要加载的资源。

加载后由 `index.js` 将数组转换为便于查询的 Map/索引；配置校验失败时显示明确的加载错误，不让 Phaser 在半初始化状态下运行。

### `index.js`

文件内部按以下固定区块组织，仍然是一个文件，但每个区块只承担一种职责：

1. 数据加载与配置校验。
2. 常量、工具函数和默认状态。
3. 状态读写、属性重算、境界/修炼、装备/进度规则。
4. 存档、读档、导入、导出和 v1 兼容处理。
5. Phaser 配置、`MainScene`、地图、纹理、实体生成、移动、AI、波次、战斗和技能。
6. 特效、对象池、碰撞、伤害、掉落和死亡流程。
7. HUD、热栏、各面板、导航和 DOM 渲染。
8. 事件委托、键盘/鼠标/触摸/摇杆输入。
9. 启动流程、错误处理和页面生命周期。

函数命名和区块注释要明确，避免再次出现大段无法定位的匿名逻辑。可以使用闭包、对象命名空间和小型纯函数隔离职责，但不得为了形式拆出新的源文件。

### `data/`

- 只放项目自己的静态资源：图片、音频、字体、预生成地图纹理等。
- 资源按类型分子目录，例如 `data/images/`、`data/audio/`、`data/fonts/`；如果资源数量很少，可直接放在 `data/` 下。
- 所有引用从 `index.html`、`style.css` 或 `index.js` 指向 `data/...`，禁止继续引用 `src/` 下的资源路径。
- 代码生成的玩家、敌人、弹丸和地面纹理继续在 `index.js` 中生成，不为不需要的素材增加文件。

## 5. 推荐实施顺序

1. 先迁移 CSS 和 HTML 入口，确保页面骨架不变。
2. 再迁移 `data.json` 和数据校验，固定运行时输入。
3. 按依赖从底层规则到 Phaser 场景、再到 UI 和启动流程合并 `index.js`。
4. 最后处理资源路径、旧文件清理、存档兼容和回归验证。

每完成一个阶段都先通过静态服务器启动和核心冒烟流程，再继续下一阶段；不要在迁移未验证时同时改玩法规则或视觉设计。

## 6. 主要风险与处理方式

| 风险 | 处理方式 |
| --- | --- |
| 单一 `index.js` 过大 | 用明确区块、命名空间、纯函数和顶部目录注释控制可读性，不再新增源码文件 |
| JSON 无法保存函数 | 将成就/事件条件改为数据描述，由 `index.js` 解释执行 |
| fetch 在 `file://` 下失败 | 统一要求通过静态 HTTP 服务器运行，并在加载失败时显示错误提示 |
| 旧存档字段变化 | 保留 `xiuxian_save`，实现字段补全和 v1 迁移，不直接覆盖原数据 |
| 资源路径迁移遗漏 | 阶段 0 建立清单，阶段 5 用浏览器网络面板逐项检查 404 |
| 合并时引入重复监听或重复初始化 | 所有监听集中在启动区块，并提供初始化保护；重新加载前销毁旧 Phaser Game |
| 大文件合并导致战斗回归 | 先保持现有公式和更新顺序，只做路径/模块合并；玩法调整单独进行 |
