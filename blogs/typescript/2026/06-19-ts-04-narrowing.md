运行时检查和类型收窄连接了不可信输入与安全代码。

![TypeScript 类型收窄动态示意图](images/06-19-ts-04-narrowing.svg)

## 为什么值得理解

类型收窄连接了运行时事实与静态类型。外部输入先是 unknown，经过可靠检查后才能被当作具体数据使用，这比直接断言更接近真实安全。

## 工作原理

typeof 适合基本类型，instanceof 检查原型链，in 判断属性存在，判别字段支持联合分支。自定义类型守卫必须返回与实际检查一致的谓词。

## 实战场景

WebSocket 收到未知消息时，先验证它是对象，再检查 type 和该分支必需字段。通过后业务代码才能安全读取 payload，而未知消息进入日志或忽略。

## 常见误区

常见误区是只检查某个属性存在却不验证其类型，或写一个永远返回 true 的守卫欺骗编译器。truthy 检查还会错误排除 0 和空字符串。

## 实践清单

- 检查后再访问可选字段。
- 为领域状态添加稳定的判别字段。
- 类型守卫必须与真实运行时行为一致。
- 让静态类型与真实运行时数据保持一致
- 将关键约束纳入类型检查和自动化测试

## 动手练习

为三种 API 响应编写守卫，准备 null、数组、缺字段和错类型输入。让编译器在每个分支显示准确类型，并验证守卫与运行结果一致。

## 小结

学习“TypeScript 类型收窄”时，类型只是表达约束的工具。只有把运行时校验、状态变化和实际构建结果一起验证，才能真正降低错误率，并让类型在需求演进中持续帮助团队。
