TypeScript 的价值在于让数据形状和函数契约更早暴露问题。

![TypeScript 类型收窄流程](images/type-narrowing-flow.svg)

## 为什么值得理解

TypeScript 类型系统让函数、对象和状态之间的关系在运行前可检查。它减少字段拼错和分支遗漏，也让编辑器能提供可靠补全，是多人协作中的可执行文档。

## 工作原理

TypeScript 使用结构类型：只要成员形状兼容，就可以赋值。联合类型表达多种可能，交叉类型合并能力，控制流分析根据运行时检查逐步收窄类型。

## 实战场景

接口返回 User | NotFound 时，调用方必须判断判别字段后才能读取用户信息。相比 nullable 字段堆在一个对象里，联合类型能排除“既成功又失败”的矛盾状态。

## 常见误区

不要用 any 暂停整个类型系统，也不要把类型断言当转换。编译通过不代表外部 JSON 符合声明，运行时边界仍需校验。

## 实践清单

- 先为边界数据定义类型。
- 用联合类型表达有限状态。
- 避免用 any 关闭所有检查。
- 让静态类型与真实运行时数据保持一致
- 将关键约束纳入类型检查和自动化测试

## 动手练习

把一个接收 unknown 数据的函数改成判别联合，覆盖正常、缺失和错误状态。开启 strict 后修复所有隐式 any 与空值问题。

## 小结

学习“TypeScript 类型系统入门”时，类型只是表达约束的工具。只有把运行时校验、状态变化和实际构建结果一起验证，才能真正降低错误率，并让类型在需求演进中持续帮助团队。
