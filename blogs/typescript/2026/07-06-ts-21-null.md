空值语义不清会让前端代码充满非空断言。

![TypeScript null 与 undefined动态示意图](images/07-06-ts-21-null.svg)

## 为什么值得理解

null 与 undefined 应表达不同业务含义：一个可能表示明确为空，另一个表示缺失或未赋值。统一语义后，非空断言和隐蔽默认值会明显减少。

## 工作原理

可选属性读取时得到 undefined，联合类型要求调用方收窄。空值合并 ?? 只在 null 或 undefined 时使用默认值，不会覆盖 0、false 和空字符串。

## 实战场景

用户昵称缺失可表示 undefined，明确清除昵称可在更新请求中发送 null。服务端与前端需要对这两种操作达成契约。

## 常见误区

使用 value || fallback 会错误覆盖合法假值，连续写 ! 则把风险推到运行时。把所有字段同时标成 optional 和 nullable 会扩大无效状态。

## 实践清单

- 先定义缺失与空值的业务含义。
- 在边界做一次规范化。
- 避免用 || 覆盖合法的 0、false 和空字符串。
- 让静态类型与真实运行时数据保持一致
- 将关键约束纳入类型检查和自动化测试

## 动手练习

为配置、表单和更新请求分别定义空值语义，开启 strictNullChecks。准备 0、false、空字符串、null 与 undefined 测试默认逻辑。

## 小结

学习“TypeScript null 与 undefined”时，类型只是表达约束的工具。只有把运行时校验、状态变化和实际构建结果一起验证，才能真正降低错误率，并让类型在需求演进中持续帮助团队。
