Mock 用于控制不稳定依赖，最常见的错误是 patch 错了查找位置。

![Python Mock 的正确打开方式动态示意图](images/06-05-python-15-mocking.svg)

## 为什么值得理解

Mock 用于隔离时间、网络和外部服务等不可控边界。它应帮助构造失败场景，而不是复制实现细节或证明真实协议兼容。

## 工作原理

patch 必须作用于被测模块查找名称的位置。return_value 定义结果，side_effect 模拟异常或序列，spec 能限制 Mock 只暴露真实接口成员。

## 实战场景

测试通知服务时，在服务模块内 patch 邮件客户端，模拟成功与超时，验证状态变化。邮件适配器本身再通过集成测试确认真实请求格式。

## 常见误区

最常见错误是 patch 原始定义位置而非使用位置，导致依赖没有真正替换。对内部调用次数断言过细，也会让安全重构频繁破坏测试。

## 实践清单

- 在被测模块查找依赖的位置 patch。
- 不要让测试过度依赖调用次数。
- 真实协议行为用集成测试补足。
- 记录输入输出、关键假设和失败样本
- 将稳定规则沉淀为测试或自动化检查

## 动手练习

选择一个调用 datetime 或 HTTP 客户端的函数，先故意 patch 错位置观察结果，再使用 spec 修正。重构内部实现，确认行为测试仍然通过。

## 小结

学习“Python Mock 的正确打开方式”时，先从真实输入和失败边界出发，再选择语言特性或库。保留可重复示例、测试和观察数据，才能判断方案是否真的可靠，也方便未来升级依赖或调整实现。
