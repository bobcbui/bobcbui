文件上传涉及路径、大小、类型和存储权限多个风险面。

![Python 文件上传安全检查动态示意图](images/06-10-python-20-file-security.svg)

## 为什么值得理解

文件上传同时涉及路径、内容、大小、存储和访问控制。客户端提供的文件名与 MIME 类型都不可信，服务端必须独立生成标识并验证内容。

## 工作原理

安全流程通常先限制请求大小，再写入受控临时文件，检测真实类型并扫描内容，最后移动到不可执行存储。下载通过权限检查和安全响应头提供。

## 实战场景

用户上传头像时，可生成随机对象键，只允许解码后的图片格式，并重新编码去除附加内容。原始文件名仅作为展示元数据保存。

## 常见误区

简单 replace('../','') 不能可靠阻止路径穿越，扩展名白名单也无法识别伪装脚本。上传目录若由 Web 服务器直接执行，风险会进一步放大。

## 实践清单

- 不要直接信任用户提供的文件名。
- 限制大小并校验真实内容类型。
- 上传目录不应默认具备脚本执行能力。
- 记录输入输出、关键假设和失败样本
- 将稳定规则沉淀为测试或自动化检查

## 动手练习

构造包含双扩展名、超大内容和路径片段的测试文件，验证上传流程拒绝或安全重命名。确认未授权用户不能下载他人文件。

## 小结

学习“Python 文件上传安全检查”时，先从真实输入和失败边界出发，再选择语言特性或库。保留可重复示例、测试和观察数据，才能判断方案是否真的可靠，也方便未来升级依赖或调整实现。
